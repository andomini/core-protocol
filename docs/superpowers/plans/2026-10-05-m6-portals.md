# M6 (foundation) — portal layer, ads, storage, telemetry, packaging

Branch `m6-portals` (worktree `core-protocol-m6`), on top of M2b (`c8b1be5`). Runs in parallel with M3/M4/M5:
build the infrastructure plus the call sites that exist today; keep gameplay edits to one-line hooks.

## Tasks

### T1 Portal layer (`src/portal/`) — TDD
- `Portal.ts` (interface), `PortalGuard.ts`, `LocalPortal.ts`, `CrazyGamesPortal.ts`, `PokiPortal.ts`, `index.ts`
  (`createPortal()` picks the adapter from `__PORTAL__`; a DEV-only `?portal=crazygames|poki` override lets the
  smoke run the real adapters against a fake SDK).
- Changes vs Merge Wall:
  - `onAdStarted` on all three adapters (Poki: the `commercialBreak/rewardedBreak(onStart)` argument; Local: fake
    overlay fires it after ~300 ms), so audio mutes only when the ad really starts.
  - Late init: when `init()` settles after the boot cap, the guard replays the lifecycle (loadingFinished,
    gameplayStart if wanted) and fires an availability change (`PortalGuard.portalReady()`).
  - Storage moves to `storage(): KeyValue` (see T3); expected failure paths log with `console.debug`.
- Tests: `tests/portalGuard.test.ts`, `tests/crazygamesPortal.test.ts` (adapted + late-init replay + onAdStarted).

### T2 Ads service + midgame policy — TDD
- `src/portal/adPolicy.ts` (pure): `MidgamePolicy` with an injected clock; data in `src/data/ads.json`
  (`midgameMinGapS` 180, `midgameSkipFirstBreaks` 1, timeouts, toast text/time).
- `src/portal/ads.ts`: `Ads` = `rewarded(placement)`, `midgame(trigger)`, `available` + `onAvailable(cb)`,
  `running` + `onAd(cb)`; telemetry `ad_request`/`ad_result`; toast on rewarded failure only (`src/portal/toast.ts`, DOM).
- Tests: `tests/adPolicy.test.ts`, `tests/ads.test.ts` (fake guard + fake clock).

### T3 Storage — TDD
- `src/portal/storage.ts`: `KeyValue` (localStorage-shaped), `localKV()` (try/catch + memory fallback),
  `SaveSlot<T>` with envelope `{v, data}`, migrations `n → n+1`, `.bak` backup of corrupt/future blobs, refuses to
  overwrite a future-version envelope. CrazyGames `storage()` = SDK.data only if the key was read from it.
- Tests: `tests/storage.test.ts`.

### T4 Telemetry — TDD for the buffer
- `src/telemetry/Telemetry.ts` (ring buffer ≤ 200 KB in localStorage, deviceId + runIndex in their own key),
  `src/telemetry/DevOverlay.ts` (lazy chunk; `~` in DEV, or `?telemetry=1` in any build), `tools/telemetry-report/report.ts`.
- Events: `session_start`, `run_start {seed,tier,deviceId,runIndex}`, `wave_reached`, `purchase`, `death {wave,time,energy}`,
  `ad_request`, `ad_result`, `session_end`.
- Tests: `tests/telemetry.test.ts`.

### T5 Wiring (lifecycle)
- `src/services.ts` singleton; `main.ts` creates the portal, starts init (raced 2.5 s), registers first-input capture.
- `BootScene`: awaits fonts + portal init (bounded), then `loadingFinished` once, then Battle.
- `src/portal/lifecycle.ts` `BattleLifecycle`: run start / pause / death / buy / wave events → guard + telemetry;
  `requestRestart()` = midgame (policy) then `restart()`. BattleScene gets ~6 one-line hooks; the sim halts while an ad runs.
- `game.sound.mute` = portal mute OR ad audio.

### T6 Builds and packaging
- `tools/postbuild.mjs` (after every build): size (gzip initial ≤ 1 MB, raw printed), no dev hooks, no other portal
  brand, positive SDK check, relative paths, exactly one SDK tag. `tools/package.mjs` → `dist/core-protocol-<portal>.zip`.

### T7 Smoke
- `npm run ui` gains a `portal` scenario (dev server, `UI_PORT` default 5180): loadingDone once, no gameplayStart before
  input, midgame on restart (CG adapter + fake SDK) pauses then mutes on adStarted, `?ads=fail` toast, no hang.
- `tools/ui/portal-check.mjs`: boots the production builds (port 5181) with the SDK stubbed via `page.route`.
